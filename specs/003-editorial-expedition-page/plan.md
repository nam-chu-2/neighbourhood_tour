# Implementation Plan: Bells Corners — The Expedition Page

**Branch**: `003-editorial-expedition-page` | **Date**: 2026-08-21 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/003-editorial-expedition-page/spec.md`

## Summary

A single, static, long-form page that presents a twenty-five minute drive through Bells
Corners with the register of a premium expedition itinerary: a full-bleed opening
photograph with the title over it, a strip of expedition facts, an overview written for
people whose Ottawa stops at the Greenbelt, a drawn route, seven numbered stops each with a
headline, photograph and first-person story, then a closing note and credits. It is read,
not played — no progress, no unlocking, no keepsake, no sound.

Technical approach: the page is one document of semantic sections. Sections are **visible
and finished by default** in CSS; an `IntersectionObserver` adds a one-shot reveal class
only when JavaScript has run and motion is welcome, so a JS failure can never blank the
page (research R1). Photographs are generated at build time by a `sharp` script into three
widths × AVIF/WebP/JPEG with intrinsic dimensions recorded in a manifest, so every image
box is reserved before its bytes arrive (R2). Text over imagery sits on a scrim whose
contrast is guaranteed by a unit test that composites it over pure white and pure black —
bounding every photograph the author might supply (R3). The route is inline SVG that draws
itself and is marked decorative (R4). Deep links are ordinary anchors, which lets the hash
router be deleted (R6). Headlines use one self-hosted, open-licensed variable serif; body
text stays on the system stack (R7).

This plan supersedes `specs/002-radio-dial-tour/plan.md`. The dial implementation is
deleted, having first been committed to `002-radio-dial-tour` (`cab485a`) so it stays
recoverable (R8).

## Technical Context

**Language/Version**: TypeScript 5.x, Node.js 22 LTS (tooling only); browser targets iOS
Safari 16+, Chrome/Android 110+ — unchanged from 001/002.

**Primary Dependencies**: Vite 6, React 19, `vite-plugin-pwa` (offline precache), Vitest,
`@testing-library/react`, Playwright, `@axe-core/playwright`, Ajv (content schema test
only), `sharp` (build-time image generation, already present). **No new runtime
dependency**; no animation library, no map library, no font service, no server SDKs.

**Storage**: None. The page stores nothing — no `localStorage`, no cookies, no identifiers
(FR-020). This feature removes the last persistence the project had.

**Testing**: Vitest (jsdom) for the content schema, the scrim contrast invariant, the
reveal logic, and the image manifest; Playwright (iPhone 13 / Pixel 5 / Desktop Chrome) for
section order, stop rendering, deep links, scrollspy, reduced motion, offline, axe, perf
budgets, and a **JavaScript-disabled** pass asserting the full text still renders.

**Target Platform**: Mobile web (portrait ≥360 px) first, responsive to tablet, desktop and
landscape. Static hosting on GitHub Pages via the existing workflow.

**Project Type**: Static web application (single package, no backend).

**Performance Goals**: Hero image and title readable ≤3 s on a mid-range phone over
throttled 4G (SC-001); smooth scrolling top to bottom with no visible stutter (SC-003);
zero cumulative layout shift from images. Budgets: initial JS ≤60 kB gzip, largest image
variant ≤400 kB, total precache ≤15 MB.

**Constraints**: Fully offline after first load (FR-017); no external or paid service at
runtime and no secrets (FR-018); nothing about the visitor leaves the device (FR-020);
complete with motion disabled, with images absent, and by keyboard alone (SC-006); readable
contrast everywhere including over photography (FR-013, FR-019); self-hosted font must be
open-licensed with its licence committed (R7).

**Scale/Scope**: 6 visitors, one page, seven stops, ~10 sections. Cost: $0.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
| --- | --- | --- |
| `vite-plugin-pwa` (service worker) — carried from 001/002 | FR-017 requires the whole page and its imagery to work offline after first load. | The HTTP cache is unreliable across mobile browsers; hand-writing a service worker is more code and more risk than the generated precache manifest. |
| A vendored font file (+ its licence) in `public/fonts/` | The editorial register the spec is built on cannot be carried by the system stack, which renders as Times on Windows — *unstyled*, not *editorial* (R7). | A hosted font service breaks offline and adds an external runtime dependency (FR-017/FR-018). **Condition**: the face must be open-licensed and its licence file committed beside it; a font without a committed licence is not shippable. |
| Build-time image generation (`scripts/make-images.ts`) | Seven photographs at one size each would either punish mobile data or look soft on a laptop; without generated dimensions the page shifts as images land (SC-003). | `vite-imagetools` is a new dependency for what ~40 lines using the existing `sharp` does; hand-authored variants and dimensions rot the first time the author swaps a photo. |
